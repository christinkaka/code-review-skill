# Subagent 委派评审架构

## 架构概述

用户通过 TRAE Agent 聊天窗口触发代码评审，主 agent 执行确定性扫描后委派子 agent 进行代码评审，最终汇总评定决策。

```
┌─────────────────────────────────────────────────────────────┐
│  用户在 Agent 聊天窗口触发                                    │
│  例如："帮我扫描一下这个仓库的安全问题"                       │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  主 Agent 识别意图                                           │
│  ├─ 解析用户提示词                                           │
│  ├─ 选择工作流（security/quality/performance/architecture） │
│  └─ 确定扫描参数                                             │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  主 Agent 执行 scan.py（确定性扫描）                         │
│  ├─ Git diff 分析                                            │
│  ├─ 调用图构建                                               │
│  ├─ 规则引擎扫描（Semgrep）                                  │
│  └─ 生成扫描结果文件                                         │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  主 Agent 委派子 Agent 进行代码评审                          │
│  ├─ 传递扫描结果文件路径                                     │
│  ├─ 指定工作流和温度参数                                     │
│  └─ 要求子 Agent 返回结构化评审结果                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  子 Agent 执行代码评审                                       │
│  ├─ 读取扫描结果文件                                         │
│  ├─ 分析代码上下文                                           │
│  ├─ 过滤误报（低温度参数 0.1-0.2）                           │
│  ├─ 生成修复建议                                             │
│  └─ 返回结构化评审结果                                       │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  主 Agent 汇总评定决策                                       │
│  ├─ 接收子 Agent 评审结果                                    │
│  ├─ 生成最终评审报告                                         │
│  ├─ 统计摘要（问题分布、严重程度）                           │
│  └─ 输出给用户                                               │
└─────────────────────────────────────────────────────────────┘
```

## 完整工作流程

### Step 1: 用户触发

用户在 TRAE Agent 聊天窗口输入提示词：

```
帮我扫描一下 release/1.0 分支和 master 分支的代码差异，看看有没有安全问题
```

或

```
对当前仓库执行代码评审，使用严格模式
```

或

```
检查一下这个 PR 有没有安全漏洞
```

### Step 2: 主 Agent 识别意图

主 Agent 解析用户提示词，确定：
- **工作流**：security / quality / performance / architecture / comprehensive
- **扫描模式**：diff 模式 / full-scan 模式
- **Profile**：default / strict / minimal

### Step 3: 主 Agent 执行确定性扫描

主 Agent 调用 scan.py：

```bash
python scripts/scan.py \
  --repo /path/to/repo \
  --base master \
  --target release/1.0 \
  --profile default \
  --workflow security \
  --output report/
```

生成扫描结果文件：
- `report/report.json` - 结构化扫描结果
- `report/report.md` - 可读的扫描报告
- `report/summary.json` - 统计摘要

### Step 4: 主 Agent 委派子 Agent

主 Agent 委派子 Agent 执行代码评审任务：

```
请对以下代码扫描结果进行评审：

## 工作流
安全审计工作流

## 温度参数
temperature: 0.1

## 扫描结果
读取文件：report/report.json

## 评审要求
1. 分析每个问题的真实性（排除误报）
2. 评估问题的严重程度（0-1 之间的置信度）
3. 为真实问题生成具体的修复建议
4. 使用严谨的评审标准（温度 0.1）

## 输出格式
返回 JSON 格式的评审结果，包含：
- rule_id: 规则 ID
- is_valid: 是否为真实问题
- confidence: 置信度（0-1）
- enhanced_fix: 修复建议
- analysis: 分析说明
```

### Step 5: 子 Agent 执行评审

子 Agent：
1. 读取 `report/report.json`
2. 分析每个问题的真实性
3. 评估置信度
4. 生成修复建议
5. 返回结构化评审结果

### Step 6: 主 Agent 汇总评定决策

主 Agent：
1. 接收子 Agent 评审结果
2. 生成最终评审报告
3. 统计问题分布和严重程度
4. 输出给用户

## 温度参数配置

为确保代码审核的严谨性和评价的一致性，子 Agent 使用以下温度参数：

| 工作流 | 温度 | 说明 |
|--------|------|------|
| security | 0.1 | 安全审计需要最高严谨性 |
| quality | 0.2 | 代码质量评审需要较高一致性 |
| performance | 0.1 | 性能分析需要严谨性 |
| architecture | 0.2 | 架构评审需要一致性 |
| comprehensive | 0.1 | 综合评审需要严谨性 |

**低温度参数的优势**：
- **严谨性**：减少随机性，确保评审结果稳定
- **一致性**：相同代码在不同时间评审结果一致
- **准确性**：减少幻觉，提高问题识别准确率

## 优势

### 1. 清晰的职责分离
- **主 Agent**：负责流程编排和结果汇总
- **子 Agent**：专注于代码评审
- **Python 脚本**：负责确定性扫描

### 2. 无需外部 API
- 完全离线可用
- 无需配置 LLM API
- 降低成本

### 3. 严谨性和一致性
- 低温度参数确保评审稳定
- 相同代码评审结果一致
- 减少误报和漏报

### 4. 灵活性
- 可以根据需要委派不同的子 Agent
- 可以并行处理多个评审任务
- 可以自定义评审标准

### 5. 可追溯性
- 所有评审过程都有记录
- 可以审计评审决策
- 便于持续改进

## 实现细节

### Python 脚本职责

Python 脚本（scan.py）只负责：
1. Git diff 分析
2. 调用图构建
3. 规则引擎扫描（Semgrep）
4. 生成扫描结果文件

**不负责**：
- AI 评审
- 误报过滤
- 修复建议生成

### Agent 系统职责

**主 Agent**：
1. 解析用户意图
2. 调用 scan.py
3. 委派子 Agent
4. 汇总评定决策
5. 输出最终报告

**子 Agent**：
1. 读取扫描结果
2. 分析代码上下文
3. 过滤误报
4. 生成修复建议
5. 返回评审结果

## 总结

通过主 Agent 委派子 Agent 来做代码评审，可以：
1. 充分利用 TRAE Agent 的 LLM 能力
2. 通过低温度参数确保严谨性和一致性
3. 避免在 Python 脚本中调用外部 LLM API
4. 实现完全离线的代码评审工具
5. 清晰的职责分离，便于维护和扩展
